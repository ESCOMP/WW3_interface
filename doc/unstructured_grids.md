# Unstructured grids in WW3

WW3 can run on unstructured triangular meshes. PDLIB distributes the mesh across
MPI tasks, using a partition computed by ParMETIS. This is selected per grid by
`WW3_UNSTRUCT`, which the build turns into the `PDLIB` and `METIS` switches.

## Requirements

- **ParMETIS:** linked into `cesm.exe` from `WW3_PARMETIS_ROOT`, which each
  machine sets in `config_machines.xml` of ccs_config (on derecho, for intel and
  gnu with mpich). ParMETIS may not be redistributed, so it is not bundled with
  CESM.
- **ESMF mesh:** WW3 fields are nodal, but CMEPS couples on elements. So, the
  ESMF mesh has one element around each `.msh` node, in the same order as the
  nodes. Otherwise, fields are coupled to the wrong nodes, with no error. See
  `tools/ww3_msh_to_esmf.py` below.

## Running an unstructured case

```
./create_newcase --case <case> --compset W_JRA --res TL319_wu2r05 \
   --machine derecho --compiler intel --run-unsupported
```

Available grids: `wu2r05` (16160 nodes, 2 deg in the open ocean, refined to 0.5
deg along the US coast). Grid names follow `wu<open>r<coast>` in hundredths of a
degree, or `wu<res>` for uniform meshes.

`mod_def.ww3` is generated by `buildnml`, by running `ww3_grid` on the recipe in
`$DIN_LOC_ROOT/wav/ww3/grid_inp.<grid>.<date>/`. To use your own mod_def, set
`WW3_MODDEF`.

## Notes

- **Native wave history is off by default** (`HIST_OPTION=never`). To turn it
  on: `./xmlchange HIST_OPTION=ndays,HIST_N=1`. The mediator history file
  (`cpl.hx.ww3`) is separate and is controlled by
  `histaux_wav2med_file1_enabled`.
- **Timesteps are set in `wav_in`, not in the mod_def.** The cap overwrites them
  with `dtmax`, `dtcfl`, `dtcfli`, and `dtmin`, so changing them in
  `ww3_grid.nml` has no effect. Use `namelist_definition_ww3.xml` or
  `user_nl_ww3` instead.
- **UOST is not compiled.** A `&UOST` block in `namelists.nml` is ignored, and
  obstruction files are not needed.

## Adding a new unstructured grid

Using `wu2r05` as an example:

1. **Input data:** `ww3_grid.nml`, `namelists.nml`, and the `.msh` in
   `$DIN_LOC_ROOT/wav/ww3/grid_inp.<grid>.<date>/`, and the ESMF mesh in
   `$DIN_LOC_ROOT/share/meshes/<grid>_<date>_ESMFmesh.nc`.
2. **`config_component.xml`:** set `WW3_UNSTRUCT` to `TRUE`, and
   `WW3_GRID_INP_DIR` to the recipe directory.
3. **`namelist_definition_ww3.xml`:** point `grid_inp`, `grid_inp_nml`, and
   `grid_inp_mesh` to the recipe files, and set `dtmax`, `dtcfl`, `dtcfli`, and
   `dtmin`. With the implicit solver, these are usually all equal. Note that
   `dtcpl` must be a multiple of `dtmax`.
4. **`config_pes.xml`:** add a PE layout.
   task. Scope it to wave-only compsets (e.g., `DATM.*SOCN.*WW3`).
5. **ccs_config:** add a `<domain>` to `component_grids_nuopc.xml` (`nx` set to
   the mesh `elementCount`, `ny` set to 1) and a `<model_grid>` alias to
   `modelgrid_aliases_nuopc.xml`.

## Tools

- **`tools/ww3_msh_to_esmf.py`:** builds the ESMF mesh from the same `.msh` used
  in the mod_def recipe. It aborts if the mesh
  fails its checks (area, degenerate or pinched cells, node coordinates).
  ```
  ./tools/ww3_msh_to_esmf.py mesh.msh <grid>_<date>_ESMFmesh.nc
  ```
- **`tools/plot_ww3_unstr.py`:** plots a mesh (colored by resolution) or the
  fields on it, from native `.ww3.hi` or mediator `cpl.hx.ww3` history files.
  Since `cpl.hx` files don't include the connectivity, pass the `.msh` with
  `--mesh`.
  ```
  ./tools/plot_ww3_unstr.py --mesh mesh.msh --zoom "Gulf:-98,-80,18,31"
  ./tools/plot_ww3_unstr.py $RUNDIR --mesh mesh.msh --field HS --zoom -82,-60,24,46
  ```
- **`tools/latlon_to_esmf.py`:** builds an ESMF mesh for a regular lat-lon
  forcing file, for CDEPS streams that don't have one.
